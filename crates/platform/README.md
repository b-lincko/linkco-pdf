# pdfcraft-platform

Layer L7 holds operating-system services that both the desktop app (`pdfcraft-ui-egui`) and the automation tools (`pdfcraft-automation`) need. Those two crates sit on the same layer and can't depend on each other, so a helper they share lives here instead of being copied into each (`xtask/src/layers.rs` allows both edges). It has no UI toolkit dependencies. Staging uses the standard library plus the safe `rustix` wrapper for macOS flush fallback; the Linux desktop-theme portal uses `zbus`.

`staging` creates the temporary file an atomic save writes before renaming it over the target. The file is opened with `create_new`, so anything already at the name (a file, a hard link, a symbolic link even when dangling, a folder) is skipped and never written through. On Windows a folder at the name fails with "access denied" rather than "already exists", and is skipped only when something is actually there. Names carry an unpredictable 64-bit suffix from `staging_suffixes` (the standard library's keyed hash, currently SipHash-1-3, keyed from the operating system's random source), which stops a name being planted in advance but is not a CSPRNG; fixed suffixes are only for tests. At most 16 names are tried, and then the save is refused. The target's name is cut to 128 bytes on a character boundary so the staging name fits every system's limit. Each caller keeps its own name form (`.{name}.{suffix}.pdfcraft-tmp` for automation, `.{name}.pdfcraft-{suffix}.tmp` for the desktop save). Writing, closing the file before the rename, renaming and removing the staging file on failure stay with the caller.

`name` must be a single native filename. Empty/dot names, absolute or relative paths, embedded NULs and (on Windows) alternate-stream names return `InvalidInput` before truncation, suffix consumption or filesystem access. This prevents a path-shaped name from traversing out of the selected directory through a planted intermediate directory. Legal native filenames, including Unicode, hidden names and Unix backslashes, remain supported. This is an argument contract, not a guarantee against concurrent replacement of a caller-controlled parent directory.

Synthetic tests pin both name forms, the 128-byte cut, the attempt limit, refusal when no name is left, path traversal rejection, validation before side effects, valid native names and Windows-specific path/stream rejection. The planted-file, link, folder and failed-rename tests stay with each caller, where they exercise the whole save.

`sync_staged` shares the desktop's flush policy with automation: call `File::sync_all` after writing and before closing/renaming. On macOS only `ENOTSUP`/`ENOTTY` permit a plain `fsync` fallback for SMB/FUSE-style volumes; other errors fail the save. The callback parameter allows deterministic flush-failure tests without global filesystem hooks. Callers close the descriptor before cleanup, preserving Windows deletion behavior. This does not synchronize the parent directory or claim power-loss/hostile-parent-directory guarantees.
